# Update-level build and API evidence

This supplements the 2026-10-28 audit and its historical review disposition. Checked 2026-10-29 against primary documentation and the supplied assemblies. It does not replace institutional preferences with Microsoft style preferences.

| Claim | Evidence and decision |
|---|---|
| The supplied 2024 DB API is 24.3.60.0; the 2026 DB API is 26.5.0.0 and references System.Runtime 10.0.0.0. | Read PE metadata using System.Reflection.Metadata, without loading native Revit code. The 2025 files are 25.4.60.0 and reference System.Runtime 8.0.0.0. Target the supplied 2026.5 reference with .NET 10; do not infer the runtime from its directory name. |
| Both supplied year folders lack the public UI assembly. | RevitUIAPI.dll is a separate internal assembly. None of the seven supplied files exposes IExternalCommand/IExternalApplication/UIApplication. The evaluation overlay adds Nice3point.Revit.Api.RevitAPIUI 2024.3.60 and 2026.4.10. The 2026 UI is an earlier same-year build; exact 26.5 UI matching and host loading remain unverified. Original files are unchanged. |
| Runtime updates and year-level API migrations are distinct. | [Autodesk's 2025/2026 runtime announcement](https://blog.autodesk.io/autodesk-desktop-products-2025-2026-net-10-updates/) says the .NET 10 update itself does not change the API and existing add-ins may continue working. That does not make new .NET 10 binaries compatible with earlier .NET 8 hosts. |
| Element identities changed width in 2024; IntegerValue is gone in 2026. | [Tammik's Autodesk 2024 changes](https://blog.autodesk.io/whats-new-in-the-revit-2024-api/) explains the 64-bit migration. [The 2026 ElementId reference](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/44f3f7b1-3229-3404-93c9-dc5e70337dd6.htm) exposes Value/Int64. Local 24.3/25.4 metadata contains get_IntegerValue; 26.5 does not. This resolves the earlier review's uncertainty about removal. |
| Parameter-group overloads were removed in 2025. | [Tammik's Autodesk 2025 changes, §1.16](https://blog.autodesk.io/whats-new-in-the-revit-2025-api/) lists FamilyManager.AddParameter/ReplaceParameter overloads taking BuiltInParameterGroup. Use the release-specific ForgeTypeId overloads, not runtime-based conditional guesses. |
| ElectricalSystem has specific 2026 obsoletions. | Autodesk's obsolete messages direct [WireSizeString to CableSize](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/51fad9c3-b6a4-a8b3-95b2-beafff72f994.htm), [WireType to CableType](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/d605965d-bbed-c3c9-14fa-2d040ec76dca.htm); [VoltageDrop has no replacement](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/2f7d179a-a6c3-375b-d184-cc796e918f5d.htm). These are deprecations, distinct from the IntegerValue removal. |
| Load-context settings predate 2027. | [Autodesk's 2026 developer guide](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API/files/Revit_API_Developers_Guide/Introduction/Add_In_Integration/Revit_API_Revit_API_Developers_Guide_Introduction_Add_In_Integration_Add_in_Dependency_Isolation_html.html) documents optional UseRevitContext=false, default true, and ContextName. Corrected the prior implication that these settings originated in 2027. |
| Windows targeting enables cross-compilation. | [Microsoft NETSDK1100 guidance](https://learn.microsoft.com/en-us/dotnet/core/tools/sdk-errors/netsdk1100) documents EnableWindowsTargeting for Linux/macOS. A WPF net10.0-windows smoke build passed on Linux with 0 warnings/errors. This is not WPF/Revit execution. |
| Runtime APIs also need version gates. | [Microsoft documents removal of in-box BinaryFormatter in .NET 9](https://learn.microsoft.com/en-us/dotnet/core/compatibility/serialization/9.0/binaryformatter-removal), so it also cannot be revived by the old switch on .NET 10. Serialization already reflects this; the AOT reference's stale switch list is now qualified. The C# skill correctly labels ThrowIfNull as .NET 6+; net48 cannot use newer BCL APIs merely by selecting a new compiler. |
| Binary floating-point can misround quantity boundaries. | [Microsoft numeric-type documentation](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/floating-point-numeric-types) explains decimal representation error. Executing the baseline expression `(int)Math.Ceiling(100 * 1.10)` produced 111, expected 110. The new domain guidance calls for exact quantity arithmetic and boundary tests, not a benchmark-specific formula. |

The benchmark uses the official Linux SDK 10.0.111, downloaded from Microsoft's release metadata and verified against its published SHA-512. Runtime 8.0.30 is also available for portable tests. DLL hashes, package provenance, metadata inspection output and exact build logs are retained under `/home/adam/github/revit-dotnet-skills-reviews/2026-10-29-iterations/`.

The Building Coder's API-context/thread-safety guidance remains intact: materialize detached values in a valid callback; keep calculations and reporting out of API loops; use no transaction for this read-only task. No performance claims are inferred from compilation or synthetic domain tests.
